# Bug Brief: 2026-07-12-doctor-control-center-wikilink

- status: reproduced-agent-local
- bug_id: 2026-07-12-doctor-control-center-wikilink
- source: installed-runtime manual archive trial

## Symptom

After a successful `archive-import`, Doctor reports `broken-index-link` for
`[[wiki/sources/archive-trial]]` although
`<control-center>/wiki/sources/archive-trial.md` exists.

## Expected

Control-center-relative Wikilinks generated by Core projections resolve without
a broken-link finding.

## Evidence And Reproduction

- Temporary Vault archive preview/apply and byte checksum verification succeed.
- Generated `wiki/index.md` contains `[[wiki/sources/archive-trial]]`.
- The proxy file exists, but `doctor validate --fail-on error` returns exit 1.
- `resolve_wikilink()` tries `vault_root` and `wiki_root` for directory targets,
  but `check_links()` does not provide `control_center` as a resolution root.

## Scope

- active: Doctor Wikilink resolution, caller wiring, regression test
- read-only: projection renderer and archive trial fixture
- excluded: archive transaction, registry schema, projection link format, real Vault

## Root Cause Hypothesis

Core projections intentionally emit control-center-relative links so the same
target works in both `wiki/index.md` and `ingest/index.md`. Doctor lacks the
matching control-center resolution root.

## Fix Plan

1. Add a failing real-files test for `[[wiki/sources/topic]]`.
2. Add optional `control_center` to `resolve_wikilink()` roots.
3. Pass `root.control_center` from `check_links()`.
4. Run focused, full, installed-runtime, and temporary-Vault verification.
